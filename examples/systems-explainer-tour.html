01

One request,
one finished page

You name a topic, and a teaching page comes back that explains it as a system. It runs on four pieces.

02

Piece one:
the recipe

A skill file that holds the procedure: what it needs, the steps in order, and the checks it runs before handing anything back.

  • It reads the library before it writes a word.
  • It scripts every zone as text before any HTML.
  • It won't hand over a page that fails a check.

Write the steps once. Follow them every time.

03

Piece two:
the library

Four reference files hold everything the recipe knows about teaching. The recipe points at them and never keeps its own copy.

  • Change a color token once and every future page changes with it.
  • The metaphor dictionary maps each abstract idea to an object you can draw.

Point at the shelf. Never copy the book.

04

Piece three:
the parts bin

The page is assembled from a ready-made template and a library of diagrams, not drawn from scratch.

  • The template brings the tokens, the minimap rail, keyboard stepping and draw-in motion.
  • The components bring 13 diagrams and 8 interface mock-ups, all token-styled.

Nobody should draw the same door twice.

05

The part people
get wrong

The temptation is to open the template and start drawing. Write every zone as plain text first: title, lede, the object it shows, and its one rule.

06

The one line
to type

Call the skill by name and give it a topic. Say who the page is for if it isn't obvious.

  • It works for any system: kitchens, invoicing, networks, agents.
  • The page lands in explainers/ unless you name a path.
07

Piece four:
the loop

Every correction you make gets one question: does this belong in the playbook? If it does, it goes into the library, and the next page starts from there.

  • The scoreboard: did you have to make the same correction twice?

Fix it once in the page. Fix it for good in the playbook.

08

Feeding it
new sources

When you analyze another great explainer, hand the analysis to update-playbook. It keeps the patterns and leaves the words behind.

  • New arcs, devices, metaphors and diagrams get filed where they belong.
  • Branding, characters, catchphrases and pitches get dropped.
  • Each update bumps the version and adds a changelog line.

Keep the pattern. Leave the words.

09

Make it real

One request, all four pieces at work. Each line in the finished page traces back to the piece that shaped it.

10

Still your call

This isn't zero work. The first few pages need a careful read, and the playbook only gets sharper when you correct it.

A playbook nobody corrects stays a first draft.

11

The whole system

Recipe, library, parts bin, loop: four pieces and one page each time. Start with piece one and give it a topic you know well.
